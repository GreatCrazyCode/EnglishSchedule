# Practice Plan: Coding & Code Review (代码开发与审查)

## Day 1

**Vocabulary (词汇):**
*   编码
*   代码
*   分支
*   提交
*   合并

**Sentences (句子):**
*   我已经为这个新功能创建了一个特性分支。
*   请为你的提交写一个清晰的说明。
*   我在合并分支的时候遇到了冲突。

## Day 2

**Vocabulary (词汇):**
*   冲突
*   拉取请求
*   代码审查
*   审查者
*   作者

**Sentences (句子):**
*   我已经创建了一个拉取请求，请帮忙审查一下。
*   你的代码里有一些不符合我们命名规范的地方。
*   这个函数的逻辑太复杂了，需要加一些注释。

## Day 3

**Vocabulary (词汇):**
*   评论
*   建议
*   修改
*   批准
*   重构

**Sentences (句子):**
*   我建议你把这个部分重构成一个独立的组件。
*   请不要在代码中使用硬编码的字符串。
*   审查者在我的PR上留了一些修改建议。

## Day 4

**Vocabulary (词汇):**
*   可读性
*   可维护性
*   性能
*   命名规范
*   注释

**Sentences (句子):**
*   这个问题很难复现，我需要更多时间来调试。
*   我们需要为核心逻辑编写单元测试。
*   这次的代码审查非常有帮助。

## Day 5

**Vocabulary (词汇):**
*   硬编码
*   单元测试
*   代码覆盖率
*   调试
*   遵循规范

**Sentences (句子):**
*   我已经根据你的建议修改了代码。
*   在合并之前，请确保所有的测试都已通过。
*   提高代码的可读性对于长期维护至关重要。
